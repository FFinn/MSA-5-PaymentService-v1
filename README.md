# OrchestrPay: обработка платежа

Проектная работа четвёртого спринта курса «Микросервисная архитектура».

Решение разложено по пяти заданиям:

1. `Task1` — реестр транзакций Saga.
2. `Task2` — таблица переходов состояний платежа.
3. `Task3` — архитектурное решение о размещении оркестратора.
4. `Task4` — BPMN-схема обработки платежа.
5. `Task5` — набор интеграционных и сквозных тестов.

Ключевой принцип решения: до фактического перевода контрагенту процесс выполняет только обратимые либо повторяемые действия. Фактический перевод — точка невозврата. При отказе проверки или подтверждённой невозможности перевода деньги возвращаются плательщику автоматически. Если результат списания, перевода или возврата неизвестен из-за технического сбоя, система сначала сверяет его с провайдером и не принимает финансовое решение на предположении.
