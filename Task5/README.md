# Набор интеграционных и сквозных тестов

Интеграционные тесты запускаются с Testcontainers: PostgreSQL для состояния платежа и Camunda, Redis для временных данных, брокер сообщений для команд и событий. Внешние банк и антифрод-сервис заменяются управляемыми тестовыми двойниками только на границе сети. Сквозные тесты поднимают весь контур процесса и проверяют наблюдаемый результат.

| Название | Тип | Компоненты | Предусловия |
|---|---|---|---|
| Создание платежа и передача на антифрод-проверку | интеграционный | Платёжный сервис, PostgreSQL, таблица исходящих сообщений, брокер сообщений | У плательщика достаточно средств; антифрод-сервис возвращает разрешение. **Действия:** создать платёж. **Ожидаемый результат:** платёжная операция сохранена, событие опубликовано, состояние — `FRAUD_CHECKING`. |
| Основной успешный путь платежа | сквозной | Оркестратор Camunda, платёжный сервис, сервис антифрод-проверок, провайдер перевода, PostgreSQL, брокер сообщений, сервис уведомлений | У плательщика достаточно средств; антифрод-сервис сразу возвращает разрешение; провайдер подтверждает перевод. **Действия:** создать платёж и дождаться завершения процесса. **Ожидаемый результат:** выполнены одно списание и один перевод, состояние — `COMPLETED`, клиенту отправлено уведомление. |
| Денежная операция и таблица исходящих сообщений фиксируются вместе | интеграционный | Платёжный сервис, PostgreSQL, брокер сообщений | Брокер временно недоступен. **Действия:** подтвердить списание. **Ожидаемый результат:** данные списания и запись в таблице исходящих сообщений сохранены в одной транзакции; после восстановления брокера событие отправлено ровно с одним ключом идемпотентности. |
| Повтор команды не создаёт второе списание | интеграционный | Платёжный сервис, PostgreSQL, Redis | Для платежа уже обработана команда списания. **Действия:** повторить команду с тем же ключом идемпотентности. **Ожидаемый результат:** создан один финансовый идентификатор, результат не изменился. |
| Запрет антифрода запускает автоматический возврат | сквозной | Оркестратор Camunda, платёжный сервис, сервис антифрод-проверок, PostgreSQL, брокер сообщений, сервис уведомлений | Списание подтверждено; антифрод-сервис возвращает запрет. **Действия:** дождаться завершения процесса. **Ожидаемый результат:** `REFUNDED`, один возврат на всю сумму, событие безопасности и уведомление клиенту. |
| Ручная проверка с разрешением | сквозной | Оркестратор Camunda, сервис антифрод-проверок, платёжный сервис, провайдер перевода | Антифрод-сервис возвращает «ручная проверка». **Действия:** убедиться в состоянии `MANUAL_REVIEW_WAIT`, передать решение оператора «разрешить». **Ожидаемый результат:** выполнен единственный перевод контрагенту, состояние — `COMPLETED`. |
| Ручная проверка с запретом | сквозной | Оркестратор Camunda, сервис антифрод-проверок, платёжный сервис, сервис уведомлений | Антифрод-сервис возвращает «ручная проверка». **Действия:** передать решение оператора «запретить». **Ожидаемый результат:** выполнен автоматический возврат без создания перевода контрагенту; служба безопасности получила уведомление. |
| Контрольный срок ручной проверки | сквозной | Оркестратор Camunda, таймеры Camunda, сервис антифрод-проверок, платёжный сервис | Антифрод-сервис вернул ручную проверку; окончательное решение отсутствует. В испытании срок сокращён настройкой. **Действия:** дождаться таймера. **Ожидаемый результат:** переход `MANUAL_REVIEW_WAIT → APPROVED`, записана причина решения, затем выполнен перевод. |
| Контрольный срок ответа сервиса проверок | сквозной | Оркестратор Camunda, таймеры Camunda, сервис антифрод-проверок | Антифрод-сервис не отвечает. В испытании срок сокращён настройкой. **Действия:** дождаться таймера. **Ожидаемый результат:** платёж разрешён по контрольному сроку; нет зависшего экземпляра процесса. |
| Подтверждённый отказ перевода возвращает деньги | сквозной | Оркестратор Camunda, платёжный сервис, провайдер перевода, PostgreSQL | Списание выполнено, антифрод-сервис разрешил платёж, провайдер однозначно отклоняет перевод. **Действия:** дождаться завершения процесса. **Ожидаемый результат:** переход в `RETURNING`, один автоматический возврат, конечное состояние — `REFUNDED`. |
| Неоднозначный ответ на перевод не вызывает преждевременный возврат | сквозной | Оркестратор Camunda, провайдер перевода, платёжный сервис | Провайдер получил команду перевода, но ответ потерян. **Действия:** дождаться сверки. **Ожидаемый результат:** состояние `TRANSFER_RECONCILIATION`; при подтверждении перевода — `COMPLETED`, при неподтверждении — `REFUNDED`. До сверки возврат не выполняется. |
| Повтор уведомления не изменяет финансовый результат | интеграционный | Сервис уведомлений, брокер сообщений, PostgreSQL | В таблице исходящих сообщений есть событие о возврате; первая доставка уведомления завершилась ошибкой. **Действия:** повторить доставку. **Ожидаемый результат:** клиент получает одно логическое уведомление, сумма и состояние платежа не изменяются. |
| Восстановление процесса после перезапуска | сквозной | Camunda, PostgreSQL, платёжный сервис, брокер сообщений | Процесс находится в `MANUAL_REVIEW_WAIT` или `TRANSFER_RECONCILIATION`. **Действия:** перезапустить оркестратор. **Ожидаемый результат:** экземпляр восстановлен с тем же идентификатором и продолжен строго с сохранённого состояния. |

## Архитектурные проверки в непрерывной поставке

1. В каждом запуске выполняются модульные тесты и проверки архитектурных правил.
2. Затем запускаются интеграционные тесты с Testcontainers.
3. Сквозные тесты выполняются перед выпуском и по ночному расписанию, так как поднимают больше компонентов.
4. В качестве артефактов сохраняются журналы контейнеров, история экземпляра Camunda и сообщения очереди недоставленных сообщений.

Для JVM-части сервиса правила ArchUnit должны запрещать прямой доступ веб-слоя к репозиториям, зависимости домена от Camunda, Spring и SQL, а также циклические зависимости между пакетами. Это не заменяет нагрузочные испытания, но не даёт постепенно нарушать границы архитектуры.
